# 0.23.1：原生源码、查询与升级

本版把Rime核心与Lua/Predict改为从固定源码构建，保留完整词库和当前输入能力。当前三个ABI不再链接provider的librime.a，构建入口核对源码锁、插件选择和依赖摘要。

## 已发现并处理的内容

0.23.0的三个ABI实际包含Octagram、Lua和Predict；原先说明漏列插件。Octagram固定快照声明[GPL3](https://github.com/lotem/librime-octagram/blob/dfcc15115788c828d9dd7b4bff68067d3ce2ffb8/LICENSE)。本应用没有配置其grammar/language或.gram模型，故在新源码构建中排除；BSD许可的Lua/Predict保留。此举不为应用自有代码选择许可证，也不解决过去发布的所有事项。其他旧包尚未逐一审查。

来源锁固定10个上游快照、Boost1.90.0、18份底层依赖静态库和306个实际头文件。Rime及插件C/C++未改动，Lua的构建查找适配由本项目提供。六个底层依赖仍是已认证的provider产物，尚未全部独立重建，阻断明确保留。新增插件、UTF8、Darts、X11、RapidJSON、Lua兼容层、glog及LLVM等说明，许可阅读器现有19组组件/34份文档，旧23份许可字节保留。

真实CMake反例检查拒绝：没有源码引擎收据、重新选择Octagram、错误引擎摘要、错误依赖。JNI的distribution_version从Gradle版本获取，移除旧0.14常量。

## 输入行为与查询

旧0.23.0与最终0.23.1分别使用新的隔离原生用户目录，在同一公共词典上执行387组全拼/九键查询，37270条候选的词语、消耗长度和顺序完全相同。完整输入569466行和英文198019义项没有删减或改写；并不据此声称全部词库排名已验收。

初次词典检查8通过/1失败，P99为65.41ms，保留原记录。诊断样本中线程CPU时间接近墙钟时间；Perfetto轨迹含FTRACE_STATUS_PARTIAL_PAGE_READ，解析被拒，没有用它推导调度结论。源码中V2全拼随机访问重复解码同一块，现保留最多64块、约16KiB偏移缓存；新增边界、最后短块及反向淘汰检查。

最终未录制的1200次纯索引查询（上限100）P99为1.763ms、最慢5.163ms；1200次带英文候选（上限12）P99为2.403ms、最慢3.655ms。均为API36/x86_64/实际16KB模拟器，不能作为真人误触、触摸绘制、全部原生调用或vivo性能结论。原生模式切换的耗时尚需控制负载后另行定位。

## 升级记录补正

旧升级脚本只检查.sst，遗漏LevelDB常见的.ldb后缀。实际基线有3个.ldb表，而不是原生库为空。表文件在正常压缩后可被改名，所以直接要求相同文件名/字节也不是充分的记录保留检查。

当前用同一锁定LevelDB构建的真实读取器，在专用模拟器打开升级前后快照的副本，启用校验和读取：6条逻辑记录全部保留，含1条已学习词与5条元数据。仅允许测试明确学习“你好”及tick的单调更新。原始快照哈希未变，没有打开正在使用的产品数据库，副本随后清理。后续检查对只有WAL的数据同样要求逻辑读取器。旧JSON和失败材料保留，之前的.sst零计数不能再被解释为无原生学习记录。

当前包的收藏2词、复习1条、SQLite全部行与设置在覆盖升级后保持一致。14项输入控制检查另会有意重置模拟器的输入习惯，并恢复收藏/复习快照；不能把这项破坏性测试说成所有旧输入习惯都没有变化。原生升级保留依据是其之前已保存的独立快照。
