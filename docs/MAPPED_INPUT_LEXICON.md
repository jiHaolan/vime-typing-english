## 数据与内存

`input/input.lex` 为 24305443 字节，包含全部公共导出记录、三个排序偏移索引和 4457 个短前缀索引。偏移索引与正文均由 FileChannel 只读映射访问；没有把 45 万个词展开成 Java Map。小型 LRU 最多缓存 64 次查询。每次结果最多 100 个，完整读音优先，随后是完成候选、简拼或仅消费左侧输入的回退；分词组句沿用有界词典搜索，不宣称是统计语言模型。

全拼、九键、简拼索引各覆盖全部 569466 条记录。短前缀最多保留 160 个按权重选出的偏移，只是查询加速；完整正文和三个完整索引没有删词。英文释义与基础输入数据分别处理，不能混合许可来源。

导出器对 `exp(log_weight)<1` 的记录省略第三列。这 75073 条仍保留在低于所有已输出权重的第 0 档，未补成 100，也不声称从舍入后的导出还原了原始精确小数。权重非负整型和所有字节边界均验证。

曾实测完整 SQLite 方案：62763008 字节，压缩 26823768 字节；未进入产品。当前映射文件与同源联想表一起压缩为 10373079 字节，保留同样的完整记录。SQLite 实验及收据保存在外部证据目录。

## 文件格式

所有整数均为小端。64 字节头部为 `VIMELEX1` 和 14 个 uint32：版本、词条数、全拼/九键/简拼索引起点、前缀表起点、正文起点、总长度、前缀数、最长编码、短前缀容量以及三个保留零值。每个完整索引存放 uint32 正文绝对偏移。

正文记录为音节串长度 uint8、去空格编码长度 uint8、UTF-8 词语长度 uint16、权重 uint32，随后是 ASCII 音节串和 UTF-8 词语。音节空格用于推导首字母；查询不解码整张词表。前缀表先列出记录偏移，再存模式、键长度、候选数、ASCII 键和候选偏移。运行时验证头部、边界与范围；部署前流式核对全部 SHA-256，校验后的临时文件原子替换。

公共文件位于 `files/lexicon-input/<dataset_id>`，生成目录与用户词典/收藏/复习分开。新文件可用后才清理旧公共版本。应用已有备份规则排除所有这些生成文件。词典损坏恢复与学习数据保留另以实际运行结果记录。

## 重建

完整来源归档自带上游输入、导出、生成器、编译收据及许可。解包后按 README 运行 `build_input_lexicon.py` 和 `verify_input_lexicon.py` 即可重建及核对基础候选，不需要手机、联网或第三方 Python 包。生成器拒绝覆盖旧输出，私有快照不进入来源归档。

`tools/run_dictionary_checks.py` 只允许专用 emulator-5580，覆盖安装测试 APK，运行真实加载/查询检查并比较已有非空学习记录。测试前用已有应用建立并保存基线；完整命令及最终 APK/修复结果见本版本验证 JSON。

完整英文/词卡的读音对应、原生内嵌第三方许可、独立语音、生产签名与收费、实体 ARM64/16KB 和多设备长期质量仍需继续。当前仍是本地 debug 预览，商业目标没有完成。

最终 ARM64 APK 为31946714字节（约31.9MB），三个ABI均低于32MiB。严格生产检查仍因debug、HTTP调试网络与预览证书失败，没有放宽生产检查。最终词典复测7项通过，另8项真实JNI通过；模拟引擎不可用后，实际InputEngine桥接能返回全长词句，随后恢复原状态。5组不完整/异常长度查询均低于100ms，结果见最终JSON。

仅将新公共`input.lex`损坏为6字节，再通过正常首页启动观察恢复，约2.046秒后文件SHA-256恢复正确；SQLite全部行和设置保持一致。当时的原生表计数遗漏.ldb，当前记录级核对另见0.23.1补正。源分级CSV再生成也重现当前词典字节与收据，未重新引入旧拼音。
